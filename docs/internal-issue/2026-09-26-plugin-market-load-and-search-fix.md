# 插件市场加载与搜索框修复

> 日期：2026-09-26 · 范围：`plugin-marketplace`（宿主）+ `PluginManagerWindow`（.NET 插件管理窗）
> 关联：`2026-09-26-plugins-section-native-migration.md`

## 1. 现象与根因

| 现象 | 根因 |
|---|---|
| 插件市场「无法加载插件」 | ① 插件运行时默认关（`pluginRuntimeEnabled:false`，省内存设计），此时市场 tab **完全空白且没有任何提示**；② 启用后 `listMarket()` 并发探测 Gitee + GitHub，但 `Promise.all` 要等最慢的源——GitHub 在部分网络 10s 硬超时才失败，市场要等满才出数据，看似"没加载" |
| 搜索框偏小 | 搜索框宿主 `Grid` 的宽度由子元素撑开：占位提示文字宽约 200px、`TextBox` 无宽；输入文字后提示隐藏，Grid 回缩到 TextBox 的最小宽度，框变小 |

实测（本机）：Electron `net.fetch` 拉 Gitee registry **200 / 12 个插件（约 2.8s）**；
GitHub raw **超时**（预期，被墙）。数据与白名单本身没有问题。

## 2. 修复

### 2.1 市场软截止（`src/main/plugin-marketplace.ts`）
- 并发探测照旧（展示各源死活），但新增 **软截止 4s**（`MARKET_REGISTRY_SOFT_DEADLINE_MS`，
  可注入）：已有源返回就立即出列表，软超时的源标记「探测超时（未等待，可点刷新重试）」；
- **全部源都超过软截止**时才回落到等真实结果（硬超时 10s 兜底），错误如实上报；
- 语义不变：优先级最高的可用源为数据源，其余可用源 standby。

### 2.2 管理窗市场 tab（`dotnet/native-windows/PluginManagerWindow.cs`）
- 运行时未启用：市场 tab 显示提示条 +「启用插件运行时」按钮（与「已安装」共用
  `MakeRuntimeBanner`）；点启用后宿主重推快照并自动加载市场；
- 已启用但源健康未回：状态行显示「正在加载插件市场…」；
- 市场为空：显示「市场暂无插件或尚未加载；点右上「刷新」重试」。

### 2.3 搜索框
- 宿主宽度固定 `320`（不再随占位文字收缩）；输入框垂直居中。

## 3. 不变量

1. 市场列表不得被单个慢/挂源拖满硬超时（软截止优先，硬超时兜底）；
2. 「未启用 / 加载中 / 空 / 失败」四种市场状态必须有明确文案，不得留空白；
3. 搜索框宽度与占位提示解耦（固定宽度）。

## 4. 验证

- `plugin-marketplace.test.ts` 新增两例：首选源挂起 → 软截止内采用兜底源（<400ms）；
  全源挂起 → 回落硬超时且错误不含「未等待」。
- 离屏渲染三态：未启用（提示条+按钮）/ 已加载（源状态 Gitee 使用中 + 卡片 + 安装按钮）/
  空（重试提示）；搜索框宽度正常。
- `dotnet build -c Release` / `tsc` 0 错；全量 **4042 通过 / 1 失败**（Git Bash 基线）；
  release 重打包 + 产物冒烟。
